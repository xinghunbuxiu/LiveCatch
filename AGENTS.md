# Agent workflow: Graphify

This repository uses the upstream Graphify skill/tool for codebase understanding. Do not treat a hand-written Mermaid diagram as a generated Graphify graph.

## Before architecture-level work

1. Check whether `graphify-out/GRAPH_REPORT.md` and `graphify-out/graph.json` exist.
2. If they exist, read the report first, then query/traverse the graph for relevant symbols and relationships. Verify important claims against the cited source files.
3. If the graph is missing or stale and the Graphify CLI is installed, run `graphify .` from the repository root. For incremental refresh, use `graphify . --update`.
4. If Graphify is unavailable in the current environment, say so explicitly. Do not fabricate graph output or claim that graph generation was run. Continue with direct source inspection when possible.

## Install the upstream tool

Install the official Graphify package and agent skill using its documented instructions:
- Package: `pip install graphifyy`
- Codex: `graphify install --platform codex`
- Other supported agents: use the matching platform option documented by the upstream project.
- Build this repository's graph from the repository root with `graphify .`.

Upstream project and current instructions: https://github.com/safishamsi/graphify

## Evidence and traceability

- Distinguish source-extracted relationships from inferred relationships; retain confidence and source locations when available.
- For call-chain answers, trace caller -> callee and verify the relevant implementation instead of relying on names alone.
- Keep separate application paths separate (Flutter and Tauri/Rust are not interchangeable).
- After changing code, refresh the graph when Graphify is available; do not commit fabricated or manually approximated `graphify-out` artifacts as if generated by Graphify.
